## Audit logging (Samba -> Wazuh)

`/etc/rsyslog.d/30-samba-audit.conf` (RainerScript) routes Samba's JSON auth audit to a raw file and
its text logs to a syslog file:
- JSON lines (`"type": "..."`) -> `/var/log/samba/audit.json` (raw, `log_format=json` on the agent).
- Text lines -> `/var/log/samba/log.samba` (RFC3164-ized, `log_format=syslog` on the agent).
- `RepeatedMsgReduction off`; `log.samba` chown `syslog:adm` 664 + logrotate `create` patched.

NOTE: Samba debug dual-channels — KDC lines land in BOTH `log.samba` and journald, so any rule
matching `full_log` KDC text fires twice (see `uc-05-t1558-004-asrep.md`).

## Wazuh agent

- Agent 4.14.8 installed (host -> SOC01 -> DC01 chain), enrolled `-A dc01` as agent `002`.
- `ossec.conf` additions (`lab/dc01/ossec.conf.additions.xml`):
  - localfile `audit.json` (`log_format=json`)
  - localfile `log.samba` (`log_format=syslog`)
  - syscheck on `/var/lib/samba/private/sam.ldb.d` with `<frequency>60</frequency>`
- FIM watches the **domain partition** `sam.ldb.d/DC=CORP,DC=LAB.ldb`, NOT the top-level `sam.ldb`
  (a TDB stub whose mtime never changes; mmap writes also defeat inotify, so only the periodic
  checksum scan fires).

## Gotchas

- **Clock skew** (recurring): no NTP. After any VM savestate/resume, `date` on SOC01/DC01 drifts
  (~13-17h). Fix before any Kerberos work: `timedatectl set-ntp off; date -s "<UTC>"` (skip `hwclock`
  — not installed), then `systemctl restart wazuh-manager` on SOC01. Kerberoast `-request` aborts with
  `KRB_AP_ERR_SKEW` if skew is present.
- `agent_control` is a manager-only tool — not present on the agent.
- Samba 4.19.5 does not return an AS-REP hash (always `ERR_PREAUTH_REQUIRED`) — see UC-05.

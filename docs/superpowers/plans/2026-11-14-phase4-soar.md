# Phase 4 SOAR — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up SOAR01 (n8n in Docker), add a malicious-domain DNS detection (Sysmon EID 22 → Wazuh rule 100047), and wire Wazuh to n8n so an alert is automatically enriched against VirusTotal and turned into an incident record + notification + audit trail.

**Architecture:** SOAR01 runs n8n in a single Docker container (SQLite, queue off) on the host-only network. WIN01's Sysmon EID 22 logs DNS queries; a Wazuh rule (100047) flags the malicious domain and a Wazuh integration script pushes that alert JSON to an n8n webhook. The n8n workflow extracts the domain, queries VirusTotal, and writes incident/notification/audit files under a bind-mounted `/srv/soar`. Power-on scenario S4 (SOC01 + WIN01 + SOAR01); DC01 and NDR01 stay off.

**Tech Stack:** VirtualBox 7.2.x, Ubuntu Server 24.04 LTS, Docker Engine (`docker.io`) + n8n, Wazuh 4.14.8, Sysmon (WIN01), VirusTotal public API, plink/pscp, PowerShell 5.1.

**Spec:** `docs/superpowers/specs/2026-11-14-phase4-soar-design.md`

## Global Constraints

- Power-on scenario **S4 only**: SOC01 (5 GB) + WIN01 (4 GB) + SOAR01 (2 GB) = 11 GB. **DC01 and NDR01 stay powered OFF for the whole phase.** SOAR01 is reached directly from the host on host-only `10.10.30.20` (no SOC01 hop).
- User runs all attack simulations (the DNS lookup); assistant builds infrastructure and verifies (AGENTS.md rule).
- Custom **Wazuh** rules are edited ONLY via the dashboard UI by the user, then synced back to the repo and committed. No raw quote chars in UI regex text — use `\x22`/`\x27` (API error 1113).
- SOAR01 stays offline after build (NAT detached). NAT is attached **only during the VirusTotal demo** (documented exception), then detached and logged.
- Secrets never in git: the VT API key lives in `lab/runbook/.local-credentials.md` (gitignored) and as an n8n credential (not exported/committed). SOAR01 local account `soaradmin/soaradmin123`.
- n8n container pinned settings: `EXECUTIONS_DATA_PRUNE=true`, `EXECUTIONS_DATA_MAX_AGE=168`, metrics off (`N8N_METRICS=false`), single container, no workers (queue off).
- The malicious domain (`<MALICIOUS_DOMAIN>`) is a runtime parameter: chosen and VT-verified **immediately before the demo** (must show `malicious > 0`). Substitute it verbatim into the rule (Task 4) and the demo (Task 7).
- Every detection gets: case doc + exercise-log rows + lessons + evidence + commit (house lifecycle). Phase 4's use case is **UC-13**.
- Remote control: host → plink SOC01 (`10.10.30.10`) and plink SOAR01 (`10.10.30.20`) directly on host-only. `ssh` inside a piped remote script MUST use `< /dev/null` (stdin gotcha).
- Clock gotcha: after any SOC01/SOAR01 savestate, check `date` first; persist `clocksource=acpi_pm` on SOAR01 via GRUB.
- Grep self-match gotcha: `sudo grep` on alerts.json emits a rule-5402 alert containing the grep command. Pipe `grep -v COMMAND` and grep the description phrase, not the rule id.
- Wazuh 4.14 rotates alerts/archives daily; yesterday's alerts are in rotated files, not live `alerts.json`. Use `zgrep` for older days.

### Task 6: Build the n8n workflow

**Files:**
- Create: `lab/soar01/workflow.json` (exported workflow — does NOT contain the API key)
- Create: `lab/soar01/workflow.md` (plain-language description of the 7 nodes)

**Interfaces:**
- Consumes: n8n container (Task 2); the webhook path `/soar` (POSTed by Task 5).
- Produces: a workflow that, on webhook POST, extracts the domain, queries VT, and writes `incidents/<alert-id>.json`, `notifications/latest.json`, and an appended `audit.log` line under `/srv/soar`.

- [ ] **Step 1: Create the VT credential (user, n8n UI)**

n8n → Credentials → New → **Header Auth**: name `x-apikey`, value `<VT API key>`. (Key stays in n8n's DB; never exported.)

- [ ] **Step 2: Build the workflow (7 nodes)**

Add nodes in this order (names must match the expressions below):

1. **Webhook** (trigger) — Method `POST`, Path `soar`, Respond `Immediately`. This is the entry; production URL = `http://10.10.30.20:5678/webhook/soar`.
2. **Code** node `extract` (Run Once for All Items), JavaScript:
```js
const a = $input.first().json;
return {
  alert_id: a.id,
  rule_id: a.rule?.id,
  agent: a.agent?.name,
  timestamp: a.timestamp,
  domain: a.data?.win?.eventdata?.queryName || null,
  raw: a
};
```
3. **HTTP Request** node `vt-lookup` — Method `GET`, URL `https://www.virustotal.com/api/v3/domains/{{ $json.domain }}`, Authentication: the `x-apikey` Header Auth credential.
4. **Code** node `build-incident` (Run Once for All Items), JavaScript:
```js
const prev = $('extract').first().json;
const vt = $('vt-lookup').first().json;
const s = vt.data?.attributes?.last_analysis_stats || {};
const verdict = { malicious: s.malicious ?? 0, suspicious: s.suspicious ?? 0, harmless: s.harmless ?? 0, undetected: s.undetected ?? 0 };
const reputation = vt.data?.attributes?.reputation ?? 0;
const domain = vt.data?.id ?? prev.domain;
const incident = {
  incident_id: prev.alert_id,
  created_at: new Date().toISOString(),
  alert: prev.raw,
  enrichment: { source: 'virustotal', domain, verdict, reputation, permalink: `https://www.virustotal.com/gui/domain/${domain}` }
};
return {
  alert_id: prev.alert_id,
  domain,
  incident,
  notification: {
    severity: 'high',
    message: `Analyst paged: DNS query to known-malicious domain ${domain} (rule ${prev.rule_id}) on ${prev.agent}. VT: ${verdict.malicious} vendors malicious.`,
    alert_id: prev.alert_id,
    timestamp: incident.created_at
  },
  audit: { timestamp: incident.created_at, alert_id: prev.alert_id, domain, action: 'notify_analyst', result: 'success' }
};
```
5. **Read/Write Files from Disk** node `write-incident` — Operation `Write`, File path `/srv/soar/incidents/{{ $json.alert_id }}.json`, data `{{ JSON.stringify($json.incident) }}`.
6. **Read/Write Files from Disk** node `write-notification` — File path `/srv/soar/notifications/latest.json`, data `{{ JSON.stringify($json.notification) }}`.
7. **Read/Write Files from Disk** node `write-audit` — File path `/srv/soar/audit.log`, **Append** mode, data `{{ JSON.stringify($json.audit) }}`.

- [ ] **Step 3: Handle the version-dependent append fallback**

If the Filesystem node has no "Append" option (older/newer n8n), replace node 7 with a **Code** node using `fs` (enable via `N8N_CODE_ENABLE_BUILTIN_MODULES=fs` env on the container, or use the external task runner):
```js
const { appendFileSync } = require('fs');
appendFileSync('/srv/soar/audit.log', JSON.stringify($input.first().json.audit) + '\n');
return $input.first().json;
```
Document whichever path worked in `lab/soar01/workflow.md`.
